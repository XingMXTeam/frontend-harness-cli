# 同步概览（sync-overview）

概览是项目的长期记忆：产品能做什么、怎么搭起来的，粒度是新人五分钟能读完。每个 planner 在澄清前都读它；只有本 skill 写它。

## 什么时候用

- 某个功能到达 `done`（`harness report <feature>`）。
- 某次 replan 改变了模块边界或能力域。

绝不在澄清或成文期间用——那些步骤只在 `prd.md` 和 `tech-design.md` 里列出「概览增量」，留给你在这里处理。

## 文件

- `.harness/overview/product.md`——能力域、用户与角色、范围边界、待定方向。
- `.harness/overview/technical.md`——模块及其边界、数据来源、横切约束、架构方向。

## 流程

1. 读两份文件，以及该功能的 `prd.md` 和 `tech-design.md`（「概览增量」一节）和最终评估报告。
2. 列出变化：新增、调整、废弃——产品侧和技术侧。
3. 每条变化写成一短行放进对应小节。已有的行能覆盖就合并，不堆叠。
4. 没有稳定变化？加一行带日期的「无概览变化（<feature>）」——不要为了显得有事做而编造。
5. 尚未决定的可以写成「讨论中的方向」，绝不写成事实。

## 绝不写进概览

- 任务 id、用例 id、rubric id、提交 SHA；
- 命令、请求/响应正文、逐文件改动清单；
- PRD 或技术方案章节的副本。

## 产出（交给主 Agent）

- 3–10 行变化、模块边界是否变化（yes/no）、来自哪个功能。

## 完成标准

- 两份文件都已更新（或有带日期的「无变化」行），只有概览层内容。
