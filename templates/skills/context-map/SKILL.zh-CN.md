# 上下文地图（context-map）

被空降进陌生仓库的 Agent，出问题不是因为没本事，是因为没地图。它盲目 grep、重复造一个已经存在的工具、改了一个被另外三个功能依赖的文件。这个 skill 把地图建一次，让之后的每个会话开局就有方向。

## 什么时候用

- 第一次在一个仓库里干活，或刚加入一个新项目。
- 仓库的 AGENTS.md / CLAUDE.md 缺失、过期，或者是两千行没人能用的大杂烩。
- Agent 老在问仓库自己能回答的问题（测试怎么跑、组件在哪、什么不能碰）。
- 一次目录、命令或约定层面的重组之后。

## 流程

1. **勘察地形。** 列出顶层目录，每个用一句话说清它管什么。产出：结构一节，每条都有用途，不只是名字。
2. **收录命令。** 从 package scripts、Makefile 或 CI 配置里找到安装、运行、构建、lint、类型检查、测试的命令，并验证每条真实存在。产出：一张从真实配置抄来的命令表，绝不凭记忆。
3. **指向事实源头。** 每类事实（API 契约、设计 token、路由规则、状态约定、错误码）分别指明哪个文件或文档是权威。产出：每条一行的指针——地图只链接真相，不复制真相。
4. **标出高危区。** 列出粗心改动会放大爆炸半径的文件和目录（共享组件、全局样式、配置、生成代码、迁移脚本），以及在那里「小心」具体意味着什么。产出：一份短清单，每条带理由。
5. **记下硬规则。** 把仓库少数不可商量的约定写成祈使句（「用共享 Button，不要新建」）。产出：最多几条规则，每条都可检验。
6. **保持索引形态。** 哪一节需要超过几行，就链接到文档而不是粘贴进来。产出：整张地图两分钟内能扫完。
7. **走一遍验证。** 随机挑三个指针打开，错的、死的当场修。产出：地图里每条链接和路径至少被核过一次。

## 反模式

- ❌ 把整个 wiki 倒进 AGENTS.md。什么都装的地图没人读，而且恰恰在最重要的地方腐烂得最快。
- ❌ 命令表从 README 抄而不对真实 scripts 核验——过期命令比没有命令更糟，因为 Agent 会信它。
- ❌ 把约定写成愿望（「我们偏好干净的代码」）而不是可检验的规则（「文件保持在 300 行以内；要加先拆」）。
- ❌ 让地图化石化：仓库重组了，旧路径还留在地图里，下个会话照着一张不存在的城市的地图导航。

## 完成判据

- AGENTS.md（或仓库等价物）位于仓库根目录，覆盖：结构、已验证命令、事实源头、高危区、硬规则。
- 地图是索引：指向事实而不是复述事实，几分钟能读完。
- 其中每条路径和命令都对着当前仓库核验过。
